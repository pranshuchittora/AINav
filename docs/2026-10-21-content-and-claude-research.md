## Claude 官方资料结论

### 账号与使用方式

消费者条款要求账户资料准确，不共享账户或登录凭据；个人订阅用于本人使用。团队应考虑成员独立席位。条款也限制未经明确允许的自动访问，官方明确允许的产品能力应按各自文档判断。

来源：[Consumer Terms](https://www.anthropic.com/legal/consumer-terms)，页面生效日期 2025-10-08，本次访问 2026-10-21。

Claude Code 文档区分订阅 OAuth 与开发者 API：原生应用正常使用订阅；构建产品、服务和 Agent SDK 集成应使用 API key 或支持的云服务商。第三方不得收集、存储、中转用户 Claude 凭据或会话 token。原样运行官方 Claude Code、由用户走官方流程登录，与提取 token 后转发到其他客户端应区分说明，不能一概声称“所有包装脚本都会封号”。

来源：[Claude Code legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)，本次访问 2026-10-21。

### 地区规则的时效问题

`https://www.anthropic.com/supported-countries` 当前跳转至 [Supported Regions Policy](https://www.anthropic.com/legal/supported-regions)，页面显示生效日 **2026-11-12**，晚于本次检查日期。该版本应作为已公布的未来政策单独标注，不能直接声称它在 2026-10-21 已生效。上线前还需核对当期适用版本；用户应核对真实所在地区和产品资格，不能把换出口 IP 当作获得使用资格。

### 封禁与申诉

官方列举重复违反使用政策、从不支持地区注册、违反服务条款等原因。认为误封时，登录被封账号，从帮助文章进入申诉表；组织暂停则使用页面上的 Request a review。导出功能及可导出范围以账号页面为准。不承诺恢复成功或处理时长。

来源：[Safeguards warnings and appeals](https://support.claude.com/en/articles/8241253-safeguards-warnings-and-appeals)，本次访问 2026-10-21。

### 限流与故障

API 429 表示速率限制，应按 retry-after 等待并控制重试，不等于账号封禁。网页或客户端错误先查看状态页，再判断是否有明确 suspended / disabled 提示。

来源：[API rate limits](https://support.claude.com/en/articles/8243635-our-approach-to-rate-limits-for-the-claude-api)、[Claude Status](https://status.claude.com/)。

### 经验说法的证据边界

未发现上述官方资料为“住宅 IP 保不封”“养号几天”“固定每天几条”“充值即可免封”提供保证。单页可以澄清这些说法，但不能虚构封禁概率、稳定性排名或安全阈值。

## 待确认的单页完整范围

建议路径：`claude-account-safety.html`，标题“Claude 账号防封与申诉指南”，说明“降低违规与误判风险，不承诺零封禁”。沿用原站导航与纯静态实现，不增加依赖。

页面依次提供：

1. 快速结论与核实日期。
2. 场景选择：个人聊天、Claude Code、第三方开发、团队协作，对应官方入口与凭据类型。
3. 使用前检查清单：地区资格、账号独享、官方登录流程、凭据保护、使用政策与账单资料；属于维护建议的条目与官方规定明确区分。
4. 常见误区：IP 和养号传言、共享成品号、订阅 token 中转、付费免封；每项给证据状态。
5. 故障分流：用量不足、429、服务故障、明确封禁、组织暂停。
6. 申诉步骤与可复制的事实模板：时间、错误原文、真实地区、产品、本人使用方式、请求复核；模板不索取密码、token 或完整支付信息。
7. 工作连续性：定期保存本人资料，准备有资格使用的替代产品，发生问题后按官方流程恢复。
8. 官方来源与版本说明，地区未来政策独立提示。

接入方式：在 nav-links.json 增加首页、子页、plan 导航与 sitemap 入口；编程和 Token 专题增加相关链接；构建后检查本地入口和移动端可读性。
