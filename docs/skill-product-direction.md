# Skill 产品方向建议

2026-10-21。该文档记录设计建议，不表示已完成精选技能市场。

## 用户应该完成的事

从“我想完成什么任务”找到可用技能，判断适不适合自己的工具，然后查看安装和使用说明。生态动态用于发现候选资源，不承担“已验证可用”的承诺。

## 建议结构

| 入口 | 内容 | 核心动作 |
|---|---|---|
| 找技能 | 按编程、文档、表格、研究、设计等任务组织的精选条目 | 筛选适用客户端、查看效果与依赖 |
| 技能详情 | 用途、示例输入输出、准确的仓库路径、安装方法、版本、许可、维护状态、所需工具/网络/权限 | 查看 SKILL.md、复制安装命令、收藏 |
| 生态动态 | 普通 GitHub 项目、MCP、模型、社区讨论 | 搜索、排序、查看原始来源 |
| 我的收藏 | 浏览器本地收藏，可导入导出 | 找回、迁移自己的技能清单 |

同一个仓库可以包含多个 Skill，精选库应以“具体技能目录 + 版本”为条目，不能只以仓库名计数。Agent Skills 的基础结构是包含 SKILL.md 的文件夹；不同客户端还可能有自己的扩展字段。

来源：[Agent Skills 标准概览](https://agentskills.io/home)、[Claude Code 技能文档](https://code.claude.com/docs/en/skills)。

## 数据和质量

- 维护公开精选清单，与自动采集的原始发现数据分开；机器发现先进入候选池。
- 标注“仅收录”“已检查结构”“已实际试用”和准确验证日期，试用时记录客户端及版本。没有验证记录就不显示已验证。
- Stars、更新时间和下载量是参考信号；默认精选顺序应依据任务匹配、可复现性、维护与安装成本。
- 去重以具体技能路径为准；同名技能、仓库 fork 和不同版本保留来源关系。
- 从官方或维护者说明提取安装命令；没有明确安装方式时不生成猜测命令。
- 查看技能会执行的脚本、网络依赖和凭据需求，帮助用户在安装前判断。

## 渐进落地

1. 本轮修复：同步公开数据、显示时效、全量搜索排序、采集类别与未验证标识，保留现有入口。
2. 下一轮建议：人工核实一批常用技能，形成任务入口与详情页，加入本地收藏、复制安装命令。
3. 有真实使用反馈后再做：相似技能比较、版本变更和失效状态；不先做账号、评论和复杂评分系统。

建议优先关注“能否找到适合的技能、能否成功安装和使用”，再用收藏、查看来源、复制命令等行为观察需求；单纯扩大采集数量无法证明使用效果。

## 本轮已落地的范围
